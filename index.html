Recap

上堂課的核心觀點

AI 不只是回答問題的工具，它正在變成工作流程的一部分。差距不在於誰會用 AI，而在於誰能把 AI 放進自己的工作方式。

Chapter 01

好的產出，
從好的提問開始

Prompt 不是咒語。
它是你跟 AI 溝通的介面。

你怎麼問，決定 AI 怎麼答。問得越清楚，結果越接近你要的。

The Problem

大多數人
這樣用 AI

❌ 常見 Prompt 幫我寫一篇文案

沒有背景、沒有對象、沒有格式、沒有限制。
AI 只能猜，結果自然不會是你要的。

這不是 AI 的問題。是指令的問題。

Prompt Structure

好 Prompt 的五個元素

不需要背公式，但你需要養成把需求說清楚的習慣。

Good Prompt

同一件事，
換一種問法

✓ 結構化 Prompt 你是一位社群媒體行銷專員。
我們是一間位於桃園的青年志工協會，下週六舉辦淨灘活動。
請幫我寫一篇 Instagram 貼文，目標是吸引 18–30 歲的年輕人報名參加。
格式：標題 + 正文（150 字內）+ 3 個 hashtag。
語氣要輕鬆親切，不要太正式。

同樣是「幫我寫文案」，但 AI 現在知道你是誰、要給誰看、要什麼格式、有什麼限制。

Before / After

差別不在 AI，
在於你怎麼問。

模糊指令

「幫我寫活動公告」
「翻譯這段」
「寫個企劃」
「幫我做簡報大綱」

結構化指令

對象＋目的＋格式＋語氣
保留術語＋正式書面語
目標＋時程＋預算＋風險
5 頁＋每頁重點＋搭配圖表建議

Iterate

好文案
不是一次問出來的。

第一次的產出通常只是起點。真正的技巧在於追問、修正、精煉。AI 不怕你改，它怕你不說清楚。

迭代 ≠ 重來。每一次追問，都讓 AI 更理解你。

第一輪：產出初稿
「語氣再活潑一點」
「加一個行動呼籲」
「把第二段縮短到 50 字」
✓ 最終版本

Step 04｜Verify & Ship

交付前，
永遠要驗證。

AI 會說得很有自信。但自信不等於正確。
在按下「送出」之前，檢查這些。

事實正確？語氣對嗎？格式符合？對象會懂？有沒有遺漏？

AI 幫你做到 80 分。最後 20 分，是你的專業價值。

GitHub Pages 讓你免費把 HTML 網頁發佈到網路上。不需要買主機、不需要會後端。

What is GitHub?

GitHub
是什麼？

GitHub 是全球最大的程式碼與檔案協作平台。你可以把它想像成「程式碼版的 Google Drive」，但它還多了版本紀錄、網頁發佈、團隊協作等功能。

免費帳號就能用
儲存任何類型的檔案
記錄每一次修改
支援網頁發佈（GitHub Pages）
全球開發者都在用

Step 1

建立 GitHub 帳號

如果你還沒有帳號，現在就去註冊。過程只需要幾分鐘。

https://github.com/signup
1

前往 github.com，點選右上角 Sign up

2

輸入你的 Email，設定 密碼 和 使用者名稱

3

完成 Email 驗證（到信箱收驗證信）

4

選擇 Free 方案即可（不需要付費）

提示：使用者名稱會變成你的網址，例如 username.github.io

Step 2

建立 Repository

Repository（倉庫）就是一個放檔案的資料夾，但它有版本紀錄。

https://github.com/new
1

登入 GitHub 後，點選右上角 ＋ → New repository

2

輸入 Repository name（例如：my-first-site）

3

選擇 Public（公開，GitHub Pages 需要）

4

勾選 Add a README file

5

點擊 Create repository

Step 3

上傳你的 HTML 檔案

把你的 index.html（和 CSS、圖片等）上傳到 Repository。

https://github.com/你的帳號/my-first-site
1

進入你的 Repository 頁面

2

點選 Add file → Upload files

3

把你的檔案 拖曳 到上傳區域

4

在下方 Commit message 寫一句說明（例如：上傳首頁）

5

點擊 Commit changes

重要：主頁面的檔名一定要叫 index.html

Step 4

啟用 GitHub Pages

上傳完檔案後，還需要開啟 Pages 功能，你的網站才會上線。

https://github.com/你的帳號/my-first-site/settings/pages
1

進入 Repository → 上方選單點選 Settings

2

左側選單找到 Pages

3

在 Source 區域選擇 Deploy from a branch

4

Branch 選 main，資料夾選 / (root)

5

點擊 Save

Step 5

你的網站
上線了！

等待約 1–3 分鐘，GitHub 會自動部署。完成後你會得到一個網址：

https://你的帳號.github.io/my-first-site/

🎉 恭喜！

你的第一個網站，全世界都看得到了。

這個網址可以分享給任何人。手機也能打開。

Troubleshooting

常見問題

第一次部署一定會遇到問題，不要緊張。以下是最常見的狀況。

?

網頁顯示 404

確認你的主檔案名稱是 index.html（全小寫）。如果名字不對，GitHub 找不到首頁。

?

CSS / 圖片沒載入

檢查路徑是否正確。在 GitHub 上，大小寫有差別。Style.css 和 style.css 是不同的檔案。

?

更新了但網站沒變

GitHub Pages 有快取。按 Ctrl + Shift + R（Mac 用 Cmd + Shift + R）強制重新載入。

?

Pages 設定找不到

確認 Repository 是 Public。Private repo 的 Pages 需要付費方案。
